## Prerequisites

- A [GitHub](https://github.com) account
- An [AWS](https://aws.amazon.com) account or a Yandex Cloud account with Postbox and Yandex Data Streams

If you have any questions join [#self-host](https://discord.gg/gbsvjb9MqV) on discord.

## Step 1: Environment variables

useSend depends on AWS SES to send emails and SNS to receive email status. Along with that it also depends on Postgres as a database and Redis for queue. Copy the `.env.selfhost.example` file to `.env` and fill in the values.

<Steps>
  <Step title="AWS credentials">
  tl;dr: Login to your AWS console and create a new user with programmatic access. Attach the `AmazonSNSFullAccess` and `AmazonSESFullAccess` policies to the user. Then create a new access key for the user.

Add the following environment variables.

    ```env
    AWS_ACCESS_KEY_ID=<access-key-id>
    AWS_SECRET_ACCESS_KEY=<secret-access-key>
    ```

<Tip>
  Follow this for detailed steps: [Create AWS
  credentials](/get-started/create-aws-credentials)
</Tip>

  </Step>
  <Step title="GitHub app credentials for login">
  useSend uses GitHub authentication for login.

Use this link to [create an github app](https://docs.github.com/en/apps/creating-github-apps/about-creating-github-apps/about-creating-github-apps)

Callback URL : `https://<your-usesend-instance>/api/auth/callback/github`

Under **Permissions & events**, set **Account permissions → Email addresses**
to **Read-only**. useSend needs the authenticated user's email address to match
new accounts to team invitations.

![github app](/images/github-callback.png)

Add the following environment variables.

```env
GITHUB_ID="<your-github-client-id>"
GITHUB_SECRET="<your-github-client-secret>"
```

  <Info>If you want email/password login, please help us out with the [code](https://github.com/usesend/usesend) </Info>  
  </Step>
  <Step title="Database & Redis">
  useSend uses Postgres as a database and Redis as a queue. You need to create a new database and add the following environment variables.

If you're using docker-compose, it's all automatically done for you.

```env
DATABASE_URL="postgres://<username>:<password>@<host>:<port>/<database-name>"
REDIS_URL="redis://<username>:<password>@<host>:<port>"
```

If you're sharing a Redis instance across multiple apps and using Redis ACL for isolation, set `REDIS_KEY_PREFIX` to namespace all keys (e.g. `REDIS_KEY_PREFIX="usesend"` prefixes all keys with `usesend:`).

  </Step>
  <Step title="Next auth url and secret">
  Url is the app url you're going to use and secret is random string. You can generate a random secret using this command.

```sh
openssl rand -base64 32
```

Add the following environment variables.

```env
  NEXTAUTH_URL="https://<your-usesend-instance>"
  NEXTAUTH_SECRET="<your-usesend-secret>"
```

  </Step>
  <Step title="Email content retention (optional)">
  By default, stored email content stays in the database forever. To bound database growth, set `EMAIL_CLEANUP_DAYS` to a positive number of days. A daily job (midnight UTC) then clears the `text`, `html`, `attachments` and `headers` values for emails older than the cutoff. Delivery status and event history are kept.

```env
EMAIL_CLEANUP_DAYS=30
```

Leave it unset to keep email content indefinitely.

  </Step>
  <Step title="Image uploads (optional)">
  Images added in the email editor are stored in S3-compatible storage. The docker-compose setup runs [RustFS](https://github.com/rustfs/rustfs) for this and creates the bucket for you. Set its credentials:

```env
RUSTFS_ACCESS_KEY="<access-key>"
RUSTFS_SECRET_KEY="<secret-key>"
```

To turn uploads on, expose the RustFS API (port `9002`, bound to `127.0.0.1`) through your reverse proxy and set both URLs. The browser uploads to `S3_COMPATIBLE_API_URL`, and sent emails link to `S3_COMPATIBLE_PUBLIC_URL`, so both must be reachable from the internet. Objects in the bucket are publicly readable so images load in inboxes; nothing else is.

```env
S3_COMPATIBLE_API_URL="https://s3.example.com"
S3_COMPATIBLE_PUBLIC_URL="https://s3.example.com/unsend"
```

Leave the URLs empty to disable uploads. If you run the image without docker-compose, you can point it at any S3-compatible service (Cloudflare R2, AWS S3) by setting `S3_COMPATIBLE_ACCESS_KEY`, `S3_COMPATIBLE_SECRET_KEY`, `S3_COMPATIBLE_API_URL`, `S3_COMPATIBLE_PUBLIC_URL` and `S3_COMPATIBLE_BUCKET`.

#### Upgrading from the MinIO setup

MinIO's community edition is no longer maintained, and its `minio/minio` image has been removed from Docker Hub, so docker-compose now runs RustFS. Your existing `MINIO_ROOT_USER` and `MINIO_ROOT_PASSWORD` keep working as RustFS credentials.

RustFS starts with a new, empty `rustfs` volume. Your old MinIO volume is not touched or deleted. The stock compose file never connected the app to MinIO, so most installs have nothing in it. If you configured uploads yourself, copy the files across once after upgrading (run from the folder with your `.env`, while the new stack is up):

```sh
set -a; . ./.env; set +a
docker run -d --name usesend-minio-migrate --network usesend-prod_default \
  -v usesend-prod_storage:/data -e MINIO_ROOT_USER -e MINIO_ROOT_PASSWORD \
  minio/minio server /data --address :9000
sleep 5
docker run --rm --network usesend-prod_default \
  -e MINIO_ROOT_USER -e MINIO_ROOT_PASSWORD \
  -e NEW_KEY="${RUSTFS_ACCESS_KEY:-$MINIO_ROOT_USER}" -e NEW_SECRET="${RUSTFS_SECRET_KEY:-$MINIO_ROOT_PASSWORD}" \
  -e BUCKET="${S3_COMPATIBLE_BUCKET:-unsend}" -e AWS_DEFAULT_REGION=us-east-1 \
  --entrypoint sh amazon/aws-cli:2.34.30 -ec '
    AWS_ACCESS_KEY_ID=$MINIO_ROOT_USER AWS_SECRET_ACCESS_KEY=$MINIO_ROOT_PASSWORD \
      aws --endpoint-url http://usesend-minio-migrate:9000 s3 sync "s3://$BUCKET" /tmp/data
    AWS_ACCESS_KEY_ID=$NEW_KEY AWS_SECRET_ACCESS_KEY=$NEW_SECRET \
      aws --endpoint-url http://rustfs:9000 s3 sync /tmp/data "s3://$BUCKET"'
docker rm -f usesend-minio-migrate
```

This uses the `minio/minio` image already on your server. If your public storage URL stays the same, images in emails you already sent keep loading. Once you've checked them, you can remove the old volume with `docker volume rm usesend-prod_storage`.

  </Step>
</Steps>

## Yandex Cloud Postbox instead of SES

Set `EMAIL_PROVIDER=postbox` to send through the SES v2 compatible Postbox API.
`EMAIL_PROVIDER=ses` is the default. Postgres and Redis are still required.

```env
EMAIL_PROVIDER="postbox"
AWS_DEFAULT_REGION="ru-central1"
AWS_ACCESS_KEY_ID="<service-account-static-key-id>"
AWS_SECRET_ACCESS_KEY="<service-account-static-secret>"
AWS_SES_ENDPOINT="https://postbox.cloud.yandex.net"
POSTBOX_YDS_ENDPOINT="https://yds.serverless.yandexcloud.net"
POSTBOX_YDS_STREAM="/ru-central1/<cloud-id>/<database-id>/<stream-name>"
```

Create a Yandex Data Streams stream first. Use its full stream path, including
its database path, for `POSTBOX_YDS_STREAM`. Grant the sending service account
permission to manage Postbox identities and configuration sets, publish events
to this stream, and read its shards and records. Configure the Yandex resources
and their service accounts to allow Postbox to write to the stream.

YDS is required for delivery status, bounces, complaints, opens and clicks.
Postbox has no SNS callback; useSend polls YDS every five seconds through the
Kinesis API over HTTP/1.1. Redis stores shard checkpoints and event deduplication
keys, so keep Redis data across restarts. Configure stream retention to cover
expected application downtime. Adding a region creates configuration sets that
publish events to this stream. Use `ru-central1` and set the send rate to your
Postbox quota; Postbox does not provide the SES GetAccount quota API.

For Postbox the settings form has no callback URL. Remove any local mock
`AWS_SES_ENDPOINT` and `AWS_SNS_ENDPOINT` settings. The Postbox endpoint above
is also used by default when `AWS_SES_ENDPOINT` is unset.

Add the domain DNS records shown by useSend. The DKIM TXT value must have this
exact format, without spaces:

```text
v=DKIM1;h=sha256;k=rsa;p=<public-key>
```

Postbox has no custom MAIL FROM support. SPF belongs on the sending domain:
`v=spf1 include:spf.postbox.yandexcloud.net ~all`. If you already have an SPF
record, add this include to it instead of creating a second SPF record.

In a live test, a failed DKIM check did not recover within 15 minutes after
publishing the TXT record. For newly created domains, **Verify again** checks
that DNS matches and recreates a failed Postbox identity with the same DKIM
key. Attempts are limited to once per ten minutes and five per day per domain.
Keys are encrypted with AES-256-GCM using a key derived from `NEXTAUTH_SECRET`
and stored separately from domain API responses. Back up that secret along with
the database. Changing it prevents automatic re-verification of existing keys.
Domains added before key storage continue sending and checking status, but
cannot use automatic identity recreation.

Open and click tracking works: Postbox rewrites HTML links and adds an invisible
GIF. Turn tracking on for the domain before sending. Open and click events
arrive through YDS. A permanent Gmail bounce creates a hard-bounce suppression;
Postbox can report `bounceSubType=Undetermined`, which useSend exposes as
`General`. The Amazon SES bounce and complaint simulator addresses did not
produce simulated events in the test; use a controlled mailbox for validation.

The fork's `publish-fork.yml` workflow builds `docker/Dockerfile` for
`linux/amd64` and publishes `ghcr.io/timurkhakhalev/usesend` using `GITHUB_TOKEN`.
Pushes to `main`, the Postbox branch, and tags produce `sha-<short>` images;
the default branch also produces `latest`, and tags produce their tag name.

## Step 3: Setting up a region

In order to send emails, you need to select a region in AWS. Use a region where your users are located / where useSend is hosted. If you're confused just use `us-east-1`.

You can check available regions [here](https://docs.aws.amazon.com/general/latest/gr/ses.html)

Once you log in to useSend, it will prompt you add SES configuration.

- Add the region
- Add the callback url, which is basically the app url. Note this should be accesible from internet. This is how you get the delivery status of the emails.
- You don't need to update the send rate, it's automatically based on your account.

## Step 5: SMTP Proxy Server (Optional)

The SMTP proxy server is an optional component that allows applications to send emails through useSend using standard SMTP protocol instead of the REST API. This is useful for legacy applications, email clients, or any software that needs to send emails via SMTP.

<Tip>
  The complete source code for the SMTP proxy server is available at:
  [usesend/usesend/tree/main/apps/smtp-server](https://github.com/usesend/usesend/tree/main/apps/smtp-server)
</Tip>

### When to use the SMTP proxy:

- **Legacy applications** that only support SMTP
- **Email clients** like Thunderbird, Outlook, Apple Mail
- **Applications** that can't easily integrate with REST APIs
- **Third-party software** that requires SMTP configuration

### Docker Compose Setup

Create a `docker-compose.yml` file for the SMTP server:

```yaml
name: usesend-smtp-server

services:
  smtp-server:
    container_name: usesend-smtp-server
    image: usesend/smtp-proxy:latest
    environment:
      SMTP_AUTH_USERNAME: "usesend" # Username for SMTP authentication
      USESEND_BASE_URL: "https://your-usesend-instance.com" # Your useSend instance URL

      # Optional: SSL certificate paths for secure connections
      # USESEND_API_KEY_PATH: "/certs/server.key"
      # USESEND_API_CERT_PATH: "/certs/server.crt"

    # Optional: Mount SSL certificates
    # volumes:
    #   - ./certs/server.key:/certs/server.key:ro
    #   - ./certs/server.crt:/certs/server.crt:ro

    ports:
      - "25:25" # Standard SMTP
      - "587:587" # SMTP with STARTTLS
      - "2587:2587" # Alternative SMTP port
      - "465:465" # SMTP over SSL/TLS
      - "2465:2465" # Alternative SMTPS port

    restart: unless-stopped
```

Run the SMTP server:

```bash
docker-compose up -d
```

### SMTP Configuration

To send emails through the proxy, configure your application with these SMTP settings:

- **Host**: Your server's IP address or domain
- **Ports**: 25, 587 (STARTTLS), 465 (SSL/TLS), 2587, or 2465
- **Username**: `usesend` (or your custom `SMTP_AUTH_USERNAME`)
- **Password**: Your useSend API key
- **Encryption**: STARTTLS (ports 25, 587, 2587) or SSL/TLS (ports 465, 2465)

<Tip>
  The SMTP proxy forwards all emails to your useSend instance, so make sure your
  main useSend application is running and accessible.
</Tip>

<Warning>
  Ensure your firewall allows traffic on the SMTP ports you're using. For
  production deployments, consider using non-standard ports (2587, 2465) to
  avoid conflicts.
</Warning>
